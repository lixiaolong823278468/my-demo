# 训练中心模型训练逻辑说明（通俗版）

这份文档用尽量直白的话，把当前“训练中心”页面里的参数和后台真正做的训练流程串起来，方便你检查当前逻辑是否符合预期。

## 一句话总结

当前训练逻辑已经不是“相似法价格 + XGBoost 残差修正”的老逻辑。

现在的核心逻辑是：

1. 直接用历史数据训练“日前价格预测模型”。
2. 按时段拆开训练，每个时段都有自己的模型。
3. 每个时段会同时训练多个候选算法。
4. 训练完后，用验证集误差判断每个时段哪个算法最好。
5. 预测时，每个时段可以使用自己选出来的最佳模型。
6. 相似法现在主要作为预测页面的参考基线，不再作为模型训练目标。

也就是说，当前模型学的是：

```text
当天供需特征、日期类型、火电容量等信息 -> 实际日前价格
```

而不是：

```text
实际日前价格 - 相似法价格
```

## 训练中心页面整体分区

训练中心页面主要有四块：

1. **训练使用天数寻优**
2. **模型结构配置**
3. **价格区间模型训练**
4. **手动训练模型**

可以这样理解：

| 页面区域 | 作用 |
| --- | --- |
| 训练使用天数寻优 | 自动试不同训练天数，找一个更合适的历史窗口 |
| 模型结构配置 | 决定模型怎么分时段、是否重视高价样本 |
| 价格区间模型训练 | 训练“价格大概落在哪个区间”的分类模型 |
| 手动训练模型 | 按你当前填写的参数直接重新训练 |

## 一、训练使用天数寻优

这块的作用是：系统自动帮你试“用最近多少天历史数据训练效果更好”。

### 1. 寻优最大历史天数

页面字段：

```text
寻优最大历史天数
```

通俗理解：

系统最多往前看多少天历史数据，去试不同训练窗口。

比如填 `100`，意思是：

```text
最多只在最近 100 天范围内找最佳训练天数
```

系统不会无限往前找。

### 2. 寻优验证集天数

页面字段：

```text
寻优验证集天数
```

通俗理解：

每次试一个训练窗口时，都拿最后几天当“考试数据”。

比如填 `14`，意思是：

```text
最后 14 天不参与训练，只用来检验模型效果
```

举例：

如果某次候选窗口是最近 60 天，验证集是 14 天，那么实际过程类似：

```text
最近 60 天中的前 46 天 -> 用来训练
最近 60 天中的后 14 天 -> 用来验证
```

验证集的作用就是判断这个训练窗口效果好不好。

### 3. 每个模型最大训练轮数

页面字段：

```text
每个模型最大训练轮数
```

通俗理解：

模型最多学习多少轮。

比如填 `400`，意思是：

```text
每个候选模型最多训练 400 轮
```

但不是一定完整训练 400 轮。模型如果发现验证集效果已经不再变好，会提前停止。

### 4. 局部细搜半径

页面字段：

```text
局部细搜半径
```

通俗理解：

系统先粗略找一个比较好的训练天数，然后在它附近再细找。

比如粗搜发现 `60 天` 效果不错，局部细搜半径是 `15`，系统会再重点检查：

```text
45 天 ~ 75 天附近的训练窗口
```

这样比只粗略试几个固定天数更细一点。

### 5. 自动寻优并训练最优模型按钮

页面按钮：

```text
自动寻优并训练最优模型
```

点击后流程是：

```text
读取历史数据
-> 按候选训练天数多次训练和验证
-> 找到验证集表现最好的训练天数
-> 用这个最佳训练天数重新正式训练
-> 注册为当前默认模型
```

它不只是找参数，最后还会真的训练并启用模型。

## 二、模型结构配置

这块决定模型训练时“怎么切时段”和“是否更重视高价样本”。

这部分配置会同时影响：

1. 手动训练
2. 训练使用天数寻优
3. 价格区间模型训练

### 1. 启用高价样本加权

页面字段：

```text
启用高价样本加权
```

通俗理解：

如果打开，模型训练时会更重视高价样本。

因为电价高的时候，价格波动通常更大，也更容易出错。如果你更关心高价时段，就可以打开。

打开后，训练样本会被分成两类：

```text
普通价格样本 -> 正常权重
高价样本 -> 更高权重
```

模型训练时会更努力拟合高价样本。

### 2. 高价阈值分位

页面字段：

```text
高价阈值分位
```

通俗理解：

系统根据历史价格自动算一个“高价线”。

比如填 `0.8`，意思是：

```text
把历史价格从低到高排序
超过 80% 分位线的样本，认为是高价样本
```

也可以理解为：

```text
价格最高的约 20% 样本会被重点关注
```

注意，这个阈值不是你手填一个固定价格，而是系统根据训练数据自动算出来。

### 3. 高价权重倍数

页面字段：

```text
高价权重倍数
```

通俗理解：

高价样本在训练时要被放大多少倍。

比如填 `2`，意思是：

```text
一个高价样本的重要性约等于两个普通样本
```

如果填得太大，模型会更偏向高价时段，但普通价格时段可能会变差。

### 4. 时段模式

页面字段：

```text
时段模式
```

目前有两种：

```text
系统默认时段
自定义时段
```

通俗理解：

不是用一个模型预测全天 96 个点，而是先把一天切成几个时段，每个时段单独训练模型。

比如默认 5 段可能类似：

```text
夜间
早高峰
午间
晚高峰
深夜
```

这样做的原因是：

不同时段价格规律不一样。比如午间新能源影响大，晚高峰供需紧张，夜间负荷低。分开训练通常比一个模型硬学全天更清楚。

### 5. 切分段数

页面字段：

```text
切分段数
```

通俗理解：

你想把一天切成几段。

比如选 `6`，就是把 96 个点切成 6 个连续时段。

注意：

```text
时段越多，模型越细
但每个时段的训练样本越少
```

如果历史数据不多，时段切太细可能会导致每个模型学不到足够规律。

### 6. 时段名称、开始时间、结束时间

页面表格：

```text
时段名称
开始时间
结束时间
```

通俗理解：

这里定义一天怎么切。

比如：

```text
segment_1：00:00 - 05:00
segment_2：05:00 - 08:30
segment_3：08:30 - 16:30
...
```

训练时，每一条历史数据都会根据它的时点归到某个时段。

然后每个时段分别训练。

## 三、价格区间模型训练

这块不是预测具体价格，而是预测价格大概在哪个区间。

页面标题：

```text
价格区间模型训练
```

它和“具体价格预测模型”是两套东西：

| 模型 | 输出 |
| --- | --- |
| 价格预测模型 | 一个具体价格，比如 386.25 |
| 价格区间模型 | 一个区间，比如 300-400、400-600、>1000 |

### 1. 价格区间

页面表格：

```text
价格区间
下限
上限
说明
```

通俗理解：

你定义几个价格档位，系统训练分类模型去判断未来价格更可能落在哪个档位。

默认类似：

```text
<250
250-300
300-400
400-600
600-1000
>1000
```

### 2. 为什么要有价格区间模型

它主要用来辅助判断风险。

例如具体预测价格是 `580`，但区间模型认为：

```text
400-600 概率高
600-1000 也有一定概率
```

那说明这个点可能接近高价风险边界。

预测页面里的：

```text
最可能价格区间
区间概率
高价概率
>1000 概率
一致性提示
```

就来自价格区间模型。

### 3. 区间模型训练窗口、验证集天数、训练轮数

页面上这几个字段现在是灰色不可编辑：

```text
区间模型训练窗口
区间模型验证集天数
高价区间召回权重
```

当前逻辑是：

```text
价格区间模型复用主模型的训练窗口、验证集天数和训练轮数
```

这样可以保证：

```text
具体价格模型和价格区间模型使用的是同一批训练口径
```

避免两套模型训练范围不一致。

### 4. 区间模型也按时段选最佳算法

价格区间模型也是分时段训练的。

并且每个时段也会从候选算法里选一个表现最好的。

例如：

```text
segment_1 用 XGBoost 分类模型
segment_2 用 CatBoost 分类模型
segment_3 用 LightGBM 分类模型
```

它不是所有时段强制用同一种算法。

## 四、手动训练模型

这块是你手动指定训练参数，然后直接重训模型。

页面标题：

```text
手动训练模型
```

点击：

```text
手动重训模型
```

后，系统不会做训练天数寻优，而是直接按当前参数训练。

### 1. 训练模式

页面字段：

```text
训练模式
```

有两种：

```text
按最近 N 天训练
指定日期范围训练
```

### 2. 按最近 N 天训练

如果选择：

```text
按最近 N 天训练
```

那么页面字段：

```text
训练使用天数
```

就生效。

比如填 `60`，意思是：

```text
只用最近 60 天历史数据作为训练数据范围
```

再结合验证集天数。

比如：

```text
训练使用天数 = 60
验证集天数 = 14
```

实际会变成：

```text
最近 60 天中的前 46 天 -> 训练
最近 60 天中的后 14 天 -> 验证
```

### 3. 指定日期范围训练

如果选择：

```text
指定日期范围训练
```

则使用：

```text
训练起始日期
训练结束日期
```

通俗理解：

你明确告诉系统：

```text
只使用这个日期范围内的历史数据
```

再从这个范围的最后几天切出验证集。

### 4. 启用训练起始日期、启用训练结束日期

页面开关：

```text
启用训练起始日期
启用训练结束日期
```

通俗理解：

控制起始日期和结束日期是否真的参与过滤。

如果关闭起始日期，系统不会用这个起始日期限制历史数据。

如果关闭结束日期，系统不会用这个结束日期限制历史数据。

不过在日常使用里，一般建议明确控制训练范围，避免训练数据范围不清楚。

### 5. 手动验证集天数

页面字段：

```text
手动验证集天数
```

通俗理解：

训练数据范围最后几天不参与训练，只用来检查模型效果。

例如填 `14`：

```text
最后 14 天做验证集
前面的数据做训练集
```

验证集主要用于：

1. 算 MAE、RMSE 等指标
2. 判断不同候选模型谁更好
3. 保存验证明细，供预测页面做“最优模型排序”
4. 判断每个时段该用哪个算法

### 6. 每个模型最大训练轮数

页面字段：

```text
每个模型最大训练轮数
```

通俗理解：

每个候选算法、每个时段最多学习多少轮。

注意这里是：

```text
每个算法 × 每个时段
```

都会训练。

比如：

```text
5 个时段
3 种候选算法
```

那就是：

```text
5 × 3 = 15 个价格预测模型
```

价格区间分类模型也会按类似思路训练。

## 五、后台真正的训练流程

点击训练按钮后，后台大致按下面顺序执行。

## 第 1 步：读取历史 Excel 数据

系统先读取历史数据文件。

每一行历史数据大致代表：

```text
某一天
某一个 15 分钟点
对应的负荷、新能源、火电容量、日期类型、实际日前价格
```

一天有 96 个点。

如果历史数据里字段缺失、格式不对、价格不是数字等，会生成数据质量报告。

## 第 2 步：生成训练样本

系统会把历史数据整理成模型能看懂的字段。

当前价格预测模型主要使用的是“当天已知或可预测的供需特征”，例如：

```text
时段点号
小时
剩余负荷 / 火电空间
总负荷
新能源出力
火电开机容量
日期类型
供需相关比例
```

这里要重点注意：

```text
similar_price 不作为训练特征
residual_target 不再生成
模型不再学习“实际价格 - 相似法价格”
```

也就是说，相似法不是当前价格模型的训练目标。

## 第 3 步：按训练范围过滤历史数据

根据你在训练中心选择的参数，系统决定用哪些日期。

如果是“按最近 N 天训练”：

```text
只保留最近 N 天
```

如果是“指定日期范围训练”：

```text
只保留起始日期到结束日期之间的数据
```

如果是“训练使用天数寻优”：

```text
系统会多次尝试不同 N 天
```

## 第 4 步：按时段切分数据

系统根据“模型结构配置”中的时段配置，把每个 15 分钟点分配到某个时段。

例如：

```text
00:00 - 05:00 -> segment_1
05:00 - 08:30 -> segment_2
08:30 - 16:30 -> segment_3
```

切完后，每个时段会单独训练。

这一步很关键：

```text
不是一个模型学全天
而是每个时段有自己的模型
```

## 第 5 步：每个候选算法都训练一遍

当前训练逻辑是多模型训练。

系统会拿候选算法分别训练。

候选算法通常包括可用的：

```text
XGBoost
LightGBM
CatBoost
```

实际哪些可用，取决于本机环境是否安装了对应依赖。

假设当前有 3 种算法可用，且切了 5 个时段，那么系统会训练：

```text
XGBoost：5 个时段模型
LightGBM：5 个时段模型
CatBoost：5 个时段模型
```

合计：

```text
15 个具体价格预测模型
```

## 第 6 步：每个时段单独划分训练集和验证集

对每个时段，系统都会按日期切分：

```text
前面的日期 -> 训练集
最后 valid_days 天 -> 验证集
```

比如：

```text
训练使用天数 = 60
验证集天数 = 14
```

那么在每个时段里：

```text
前 46 天该时段的数据 -> 训练
后 14 天该时段的数据 -> 验证
```

## 第 7 步：如果启用高价样本加权，就提高高价样本权重

如果打开“启用高价样本加权”，系统会先根据历史价格算出高价阈值。

比如分位数是 `0.8`：

```text
超过 80% 分位价格的样本 = 高价样本
```

训练时：

```text
普通样本权重 = 1
高价样本权重 = 你填写的高价权重倍数
```

例如倍数为 `2`：

```text
高价样本训练影响力翻倍
```

## 第 8 步：训练具体价格预测模型

每个模型学习的是：

```text
输入：当天供需、日期、时段、火电容量等特征
输出：实际日前价格
```

也就是直接预测价格。

不是先预测相似法价格，也不是预测残差。

训练出来的模型会保存在当前训练版本目录里。

## 第 9 步：在验证集上计算误差

每个候选模型训练完后，都会在验证集上预测一次。

然后拿：

```text
预测价格
实际日前价格
```

做对比，计算指标。

主要指标包括：

| 指标 | 通俗解释 | 越大越好还是越小越好 |
| --- | --- | --- |
| MAE | 平均差了多少钱 | 越小越好 |
| RMSE | 对大误差更敏感的平均误差 | 越小越好 |
| P90 误差 | 90% 样本误差不超过多少 | 越小越好 |
| 最大误差 | 最差一个点错了多少 | 越小越好 |
| 方向准确率 | 涨跌方向判断对的比例 | 越大越好 |
| Bias | 平均偏高还是偏低 | 越接近 0 越好 |

这些指标会用于：

1. 训练中心展示
2. 模型版本对比
3. 每个时段选择最佳算法
4. 预测页面的最优模型排序

## 第 10 步：保存验证集预测明细

当前训练会额外保存一份验证集预测明细。

每条明细大概包括：

```text
模型名称
算法类型
时段
日期
点号
实际价格
预测价格
```

这份数据的作用是：

```text
预测页面可以临时选择不同排序指标，重新给每个时段的候选模型排序
```

比如你在预测页面选择：

```text
MAE(250-1000)
```

系统不是重新训练，而是从这份验证明细里筛选：

```text
实际价格在 250 到 1000 之间的样本
```

然后重新计算 MAE 排序。

## 第 11 步：每个时段独立选择最佳算法

这是当前逻辑的重点。

系统不会只选一个全局最佳算法用于所有时段。

而是：

```text
每个时段单独看哪个候选模型表现最好
```

默认评分方式可以理解为：

```text
综合分 = MAE + 0.2 × RMSE
```

综合分越小越好。

举例：

| 时段 | XGBoost | LightGBM | CatBoost | 最终选择 |
| --- | --- | --- | --- | --- |
| 夜间 | 最好 | 一般 | 一般 | XGBoost |
| 早高峰 | 一般 | 最好 | 一般 | LightGBM |
| 晚高峰 | 一般 | 一般 | 最好 | CatBoost |

最终会保存成：

```text
selected_segment_price_models
```

意思是：

```text
每个时段预测价格时应该用哪个模型
```

## 第 12 步：训练价格区间分类模型

具体价格模型训练完后，系统还会训练价格区间模型。

价格区间模型学的是：

```text
输入：同样的供需、日期、时段等特征
输出：价格属于哪个区间
```

例如：

```text
<250
250-300
300-400
400-600
600-1000
>1000
```

它的作用不是替代价格预测模型，而是在预测页面辅助判断风险。

例如：

```text
最终预测价格 = 580
区间模型认为 600-1000 概率较高
```

那说明这个点可能存在冲高风险。

## 第 13 步：可选滚动回测

如果配置启用了滚动回测，系统还会模拟过去一段时间的预测效果。

滚动回测可以理解为：

```text
站在历史上的某一天
只用它之前的数据训练
然后预测这一天
再和真实价格比较
```

这样比单次验证集更接近日常预测场景。

回测结果会用于模型版本页面展示。

## 第 14 步：写入模型元数据并注册为当前模型

训练完成后，系统会保存：

```text
模型文件
metadata.json
验证集预测明细
训练日志
价格区间模型
质量报告
```

其中 `metadata.json` 很重要，里面记录：

```text
这次训练用了哪些日期
验证集是哪几天
用了几个时段
每个时段选了哪个模型
有哪些候选算法
各模型指标
价格区间配置
高价样本加权配置
```

预测时会读取这个文件，保证：

```text
预测使用的时段结构和训练时一致
```

## 六、预测时如何使用训练结果

训练完成后，预测时的关键逻辑是：

```text
读取当前模型 metadata
读取预测文件
按训练时的时段配置切分 96 个点
每个时段读取 selected_segment_price_models 中指定的模型
分别预测
拼回完整 96 点曲线
再叠加价格区间风险结果
```

也就是说：

```text
segment_1 用 segment_1 选中的模型
segment_2 用 segment_2 选中的模型
segment_3 用 segment_3 选中的模型
```

不是所有时段都强制用同一个模型。

## 七、相似法现在在训练里的位置

这是容易混淆的一点。

当前逻辑下：

```text
相似法不再作为价格模型训练目标
```

也就是说，当前不会再训练：

```text
residual_target = 实际日前价格 - similar_price
```

也不会让模型只学这个残差。

当前具体价格模型直接学：

```text
实际日前价格
```

相似法主要用于：

1. 预测页面展示参考基线
2. 图表中显示“多条件相似基线”
3. 图表中显示“仅净负荷相似基线”
4. 滚动回测里和模型效果做对比

所以你现在看到的三条曲线含义是：

| 曲线 | 含义 |
| --- | --- |
| 最终预测价格 | 模型最终输出的价格 |
| 多条件相似基线 | 按多个相似条件找历史参考价格 |
| 仅净负荷相似基线 | 只按净负荷 / 火电空间找历史参考价格 |

相似法是参考线，不是当前价格模型的训练标签。

## 八、预测页面“分时段模型选择”和训练的关系

训练时会保存每个候选模型在验证集上的预测明细。

预测页面的“分时段模型选择”可以基于这些明细重新排序。

支持的排序指标包括：

```text
综合分
MAE
RMSE
MAE(价格范围)
P90误差
最大误差
方向准确率
```

### MAE(价格范围) 是怎么来的

比如页面输入：

```text
250 - 1000
```

系统会从验证集明细里筛选：

```text
实际日前价格 >= 250
实际日前价格 <= 1000
```

然后只在这些样本上重新计算 MAE。

注意：

```text
这个范围是在预测页面临时算的
不需要重新训练
```

它的作用是：

```text
减少极低价、极高价样本对模型排序的影响
```

如果你更关心常规价格区间，就可以用这个指标排序。

## 九、手动训练和寻优训练的区别

| 对比项 | 手动训练 | 训练使用天数寻优 |
| --- | --- | --- |
| 是否自动试训练天数 | 否 | 是 |
| 训练窗口从哪里来 | 你手动填 | 系统自动搜索 |
| 是否最终训练模型 | 是 | 是 |
| 是否使用模型结构配置 | 是 | 是 |
| 是否使用价格区间配置 | 是 | 是 |
| 适合场景 | 你已经知道想用多少天 | 不确定用多少天更好 |

简单理解：

```text
手动训练 = 你指定参数，系统照做
寻优训练 = 系统先帮你找训练天数，再正式训练
```

## 十一、你检查逻辑时可以重点看什么

如果你想判断训练是否符合预期，建议重点看这些点：

### 1. 看训练范围

确认：

```text
train_start_date
train_end_date
valid_dates
```

是否符合你填写的训练窗口和验证集天数。

### 2. 看时段配置

确认：

```text
segment_config
```

是否是你在训练中心配置的时段。

### 3. 看每个时段选择的模型

确认：

```text
selected_segment_price_models
```

是否每个时段都有自己的模型选择。

### 4. 看候选模型指标

确认：

```text
variant_metrics
variant_quality_metrics
```

可以看到不同算法的验证集表现。

### 5. 看验证集预测明细

确认：

```text
validation_predictions.jsonl
```

是否存在。

这个文件存在后，预测页面才能做“按指标重新排序”。

## 十二、几个容易误解的点

### 误解 1：现在还是 XGBoost 残差模型

不是。

当前是多候选算法直接预测价格。

### 误解 2：所有时段都用同一个最佳算法

不是。

当前每个时段可以选择不同算法。

### 误解 3：MAE(250-1000) 需要训练时固定

不需要。

它是在预测页面根据验证集明细临时计算的。

### 误解 4：相似法会参与训练

当前具体价格模型不使用相似法作为训练目标。

相似法主要是参考基线和对比线。

### 误解 5：价格区间模型会替代价格预测模型

不会。

价格区间模型只是辅助判断价格风险。

最终价格仍然来自具体价格预测模型。

## 十三、最终可以这样理解当前系统

当前系统可以理解成两层模型：

```text
第一层：具体价格预测模型
  负责输出 96 点具体价格

第二层：价格区间分类模型
  负责判断每个点落在哪个价格区间、有没有高价风险
```

具体价格预测模型又是分时段的：

```text
每个时段单独训练
每个时段单独选择最佳算法
每个时段预测时使用自己的模型
```

相似法则作为旁边的参考线：

```text
多条件相似基线
仅净负荷相似基线
```

用来帮助你判断模型预测是否明显偏离历史相似规律。
