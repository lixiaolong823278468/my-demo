## 第一部分：训练逻辑（完整细节）

### 0. 训练入口

有两条训练入口，最终都调用同一个核心函数 `train_and_register()`：

| 入口 | 触发方式 | 文件 |
|------|----------|------|
| 网页训练 | 训练中心页面点击"手动重训模型"或"自动寻优并训练最优模型" | `api_server.py` → `dayahead_core.py` |
| 命令行训练 | `python dayahead_timeseg_model.py train --xxx` | `dayahead_timeseg_model.py` → `dayahead_core.py` |

两条路径最终构造 `TrainConfig` 后调用 `train_and_register(config)`，逻辑完全一致。

### 1. TrainConfig 参数全貌

```python
@dataclass
class TrainConfig:
    history_dir: Path                          # 历史数据目录（默认"数据"）
    model_root: Path                          # 模型根目录（默认"models"）
    holiday_file: Path | None                 # 节假日文件
    valid_days: int = 14                      # 验证集天数
    training_window_days: int | None          # 训练窗口天数（None=手动日期）
    num_boost_round: int = 400                # 每模型最大训练轮数
    start_date: str | None                    # 手动起始日期
    end_date: str | None                      # 手动结束日期
    similarity_reference_days: int = 100      # 相似法参考天数
    enable_rolling_backtest: bool = True      # 是否滚动回测
    rolling_backtest_horizons: tuple = (14, 30)  # 回测天数
    segment_config: list | None               # 自定义时段配置
    high_price_weight_enabled: bool = False   # 是否启用高价加权
    high_price_quantile: float = 0.8          # 高价分位阈值
    high_price_weight_multiplier: float = 2.0 # 高价权重倍数
    price_intervals: list | None              # 价格区间定义
    train_interval_model: bool = True         # 是否训练区间模型
    train_thermal_capacity_model: bool = True # 是否训练开机容量模型
    # 区间模型独立参数（不填则复用主模型参数）
    interval_valid_days / interval_training_window_days / interval_num_boost_round
    interval_start_date / interval_end_date
    # 开机容量模型独立参数（同上）
    thermal_capacity_valid_days / thermal_capacity_training_window_days / ...
```

### 2. train_and_register() 完整执行流程

以下按代码实际执行顺序，逐一说明每个步骤的细节：

#### 步骤 1：加载历史数据 → `build_training_frame()`

```
读取"数据/"目录下所有 Excel 文件
  ├── 按文件路径识别年/月
  ├── 遍历每个 Sheet（一个 Sheet = 一天）
  │   ├── parse_sheet_date()：从 Sheet 名识别日期
  │   ├── validate_history_sheet()：数据质量检查
  │   │   ├── 字段缺失检查 → 阻塞问题直接跳过
  │   │   ├── 价格非数字检查
  │   │   └── 数据质量报告记录
  │   └── prepare_single_sheet()：解析为标准化 DataFrame
  │       ├── 只取前 96 行（一天 96 个 15 分钟点）
  │       ├── 识别列：总负荷 / 新能源 / 日前价格 / 出清概况
  │       ├── 构造特征：net_load = total_load - renewable_power
  │       ├── 构造特征：thermal_space_load_ratio
  │       ├── 构造特征：thermal_on_capacity（从文本提取火电开机容量）
  │       ├── 添加时间特征：date / period / hour / weekday / month
  │       ├── 添加日期类型：is_weekend / is_holiday / day_type
  │       └── 目标列：日前出清价格(元/MWh)
  ├── 拼接所有有效 Sheet
  ├── 缓存到 models/cache/history_raw（版本号=4，文件签名变化时重建）
  └── 返回 history_df
```

**缓存机制：**
- 根据文件路径、大小、修改时间、日期范围生成签名
- 签名不变则直接复用缓存，跳过 Excel 读取
- 缓存版本升级到 4（新增字段时自动重建）

#### 步骤 2：按时段分配 segment

```
读取 segment_config（来自 TrainConfig 或默认 SEGMENTS）
  └── 默认 5 段：
      night(1-24) / morning_peak(25-40) / midday(41-60) / evening_peak(61-80) / late_night(81-96)
  └── 当前实际使用自定义 6 段：
      segment_1(1-20) / segment_2(21-34) / segment_3(35-66) / segment_4(67-72)
      / segment_5(73-88) / segment_6(89-96)

history_df["segment"] = assign_segments(history_df["period"], segment_definitions)
```

#### 步骤 3：按训练范围过滤历史数据

```
resolve_training_date_range():
  如果 training_window_days 有值：

    从历史最新日期往前取 (training_window_days + valid_days) 天
    例如：training_window_days=97, valid_days=14 → 取最近 111 天

  如果 start_date/end_date 有值：
    按指定日期范围过滤

最后 dropna(subset=[TARGET_COLUMN, "net_load"]) 清洗必要特征缺失行
```

**重要：训练窗口天数 + 验证集天数 是一起取的。** 比如填"训练使用天数 60"+"验证集天数 14"，实际会取 74 天数据，前 60 天训练、后 14 天验证。

#### 步骤 4：计算高价样本阈值

```
如果 high_price_weight_enabled = True：
  quantile = min(0.99, max(0.5, high_price_quantile))
  high_price_threshold = history_df[目标价].quantile(quantile)

当前已训练模型实际值：quantile=0.8, threshold=323.0
  → 价格 >= 323 的样本被认为是"高价样本"
```

#### 步骤 5：创建 staging 目录 → 构建特征变体和后端矩阵

```
run_id = "run_YYYYMMDD_HHMMSS"
staging_dir = models/_staging/{run_id}/

特征变体（direct_model_variants）：
  no_lag_96: 使用 11 个基础特征（无滞后价格）
  with_lag_96: 使用 11 个基础特征 + 8 个滞后/滚动特征

模型后端（available_model_backends）：
  检查 XGBoost / LightGBM / CatBoost 是否可导入
  每个可用后端加入候选
  过滤条件：config.model_backend_keys（如指定则只训练指定后端）

训练矩阵 = 特征变体 × 模型后端 × 时段数
  当前代码（不指定过滤且三后端可导入）：2 变体 × 3 后端 × 6 段 = 36 个模型
  每个都独立训练
```

**注意：** 当前代码只有 `no_lag_96` 和 `with_lag_96` 两个直接价格特征变体，没有 `with_lag_knn_96`。因此完整候选规模是 2×后端数×时段数。当前 `models/current` 这个已训练版本只有 `no_lag_96_xgboost` 和 `with_lag_96_xgboost`，原因是该版本训练时运行环境只识别到 XGBoost；现在通过 `.venv` 启动服务后，重新训练才会纳入 LightGBM / CatBoost。自动窗口寻优的中间候选窗口训练会为了速度限制为 XGBoost；最终保存正式模型时不限制后端，会按当前运行环境中可导入的后端展开。

#### 步骤 6：遍历特征变体 × 后端，训练每个时段模型

```
train_segment_models() 内部逻辑（每个 feature_variant × backend 调用一次）：

  对每个 segment_name：
    ├── 取该时段样本 segment_df = history_df[segment == name]
    ├── dropna(subset=[目标价]) 清洗缺失
    ├── split_train_valid(segment_df, valid_days)
    │   ├── 按 date 排序取唯一日期
    │   ├── 最后 valid_days 天 = 验证集
    │   └── 其余日期 = 训练集
    ├── high_price_sample_weights()：高价样本权重计算
    │   ├── 训练集中 目标价 >= threshold 的行 → weight = multiplier
    │   └── 其余行 → weight = 1
    ├── train_backend_model(backend, train_df, valid_df, ...)
    │   ├── XGBoost: xgb.DMatrix + xgb.train(early_stopping_rounds=50)
    │   ├── LightGBM: lgb.Dataset + lgb.train(early_stopping=50)
    │   └── CatBoost: CatBoostRegressor.fit(early_stopping_rounds=50)
    │   ├── 使用 DEFAULT_XGB_PARAMS（eta=0.05, max_depth=5, ...）
    │   ├── 保存模型文件（.json / .txt / .cbm）
    │   └── 返回 best_iteration + 验证集预测结果
    ├── calculate_metrics(actual, predicted) → MAE, RMSE
    ├── summarize_prediction_errors() → bias, p90, direction_accuracy, over/under_rate
    ├── 记录 validation_records（每条：model_key, segment, date, period, actual, predicted）
    └── 汇总该时段指标 → metrics_summary[segment_name]

  返回：metrics_summary, train_dates, valid_dates
```

**验证集划分规则：**
- 按时段独立划分（不是全局统一）
- 按日期排序后，取最后 valid_days 个唯一日期作为验证集
- 如果某时段总日期数 <= valid_days，则该时段全部作为训练集、验证集为空

#### 步骤 7：汇总指标并选择最优模型

```
variant_quality_metrics = summarize_model_quality_metrics(variant_metrics)
  ├── 每个 variant 的 6 时段指标按 valid_rows 加权平均
  └── 得到每个 variant 的 final_mae / final_rmse

variant_score = final_mae + 0.2 * final_rmse  （越小越好）

selected_model_key = min(variant_quality_metrics, key=variant_score)
```

**当前已训练模型实际选中：** `with_lag_96_xgboost`。注意这是当前 `models/current` 的结果；重新用 `.venv` 训练后，若 LightGBM / CatBoost 参与，选中结果可能变化。

#### 步骤 7.5：每个时段独立选择最佳模型（selected_segment_price_models）

这是 2026-05 新增的逻辑。不是全局选一个最优后端用于所有时段，而是每个时段单独选择：

```
select_best_segment_price_models():
  对每个 segment_name：
    ├── 遍历所有 model_key 在该时段的 segment_model_score
    ├── score = final_mae + 0.2 * final_rmse
    └── 选 score 最小的 model_key

selected_segment_price_models = {
    "segment_1": "with_lag_96_xgboost",
    "segment_2": "no_lag_96_xgboost",
    "segment_3": "no_lag_96_xgboost",
    "segment_4": "with_lag_96_xgboost",
    "segment_5": "with_lag_96_xgboost",
    "segment_6": "no_lag_96_xgboost"
}
```

如果某时段没有候选模型指标，fallback 使用全局 `selected_model_key`。

#### 步骤 8：训练价格区间分类模型

```
train_interval_models(interval_history_df, ...)
  ├── 复用主模型的特征列表（feature_columns）
  ├── 按时段分别训练分类模型
  ├── 每个时段：多个后端候选（interval_xgboost / interval_catboost / interval_lightgbm）
  ├── 按实际价格生成区间标签（如 <250, 250-300, 300-400, 400-600, 600-1000, >1000）
  ├── 评估指标：命中率 / Top2命中率 / 高价召回率 / 概率质量
  └── 选择最优区间模型
```

区间模型训练使用 `interval_history_df`（默认复用主模型窗口，也可独立配置）。

#### 步骤 9：训练日级火电开机容量模型（新增）

```
train_thermal_capacity_model()
  ├── 日级特征（日均负荷、峰谷差、爬坡等）
  ├── 训练目标：火电开机容量（thermal_on_capacity）
  └── 预测日当日火电开机容量值
```

#### 步骤 10：高价概率调权效果评估

```
在验证集上评估高价概率调权效果：
  ├── 加载区间模型预测验证集的区间概率
  ├── 对高价概率高的样本做调权
  ├── 计算调权前后的 MAE/RMSE 变化
  └── 汇总 high_price_adjustment_metrics
```

调权逻辑：
- 触发条件：区间模型判断"高价概率 high_price_probability >= 0.30"
- 调权方式：在原有预测价格基础上加成（最大向上调整 120 元）
- 极端高价概率 >= 0.10 时，最大向上调整 180 元
- 基础价格需 >= 250 才参与调权

#### 步骤 11：滚动回测（可选）

```
rolling_backtest_selected_model(horizons=(14, 30))
  对每个 horizon（如 14 天、30 天）：
    遍历最近 horizon 个历史日作为测试日：
      ├── 取测试日之前的历史日作为训练池
      ├── 按时段训练临时模型
      ├── 预测测试日
      ├── 累计 actual / predicted / similarity
      └── 计算整体/分段/尖峰/低价误差

  回测输出还包括：
    ├── 多条件相似法 baseline 误差
    ├── 仅火电空间相似法 baseline 误差
    ├── 模型相对 baseline 的改善幅度
    └── 每日误差排名（最好/最差）
```

**注意：** 回测不是训练的一部分结果验证，而是额外的"模拟历史预测"评估。回测中要重新训练临时模型。

## 第二部分：预测逻辑（完整细节）

### 0. 预测入口

同样两条路径，最终都调用相同的预测管道：

| 入口 | 文件 |
|------|------|
| 网页预测 | `api_server.py` → `predict_prices()` 或 `predict_prices_compare()` |
| 命令行预测 | `dayahead_timeseg_model.py predict` → `predict_prices()` |

### 1. 完整预测流程

#### 步骤 1：prepare_prediction_inputs() → 加载所有输入

```
├── peek_forecast_target_date()：从预测文件列头解析预测日
├── prediction_history_window()：计算需要的历史数据范围
│   ├── 参考天数 = reference_days（用户指定，默认 1）
│   └── 范围 = [预测日前 max(reference_days, reference_days×8) 天, 预测日前1天]
├── load_cached_history_collection()：加载历史数据（同上缓存机制）
├── load_models(model_root)：加载当前默认模型
│   ├── 读取 models/current/metadata.json
│   ├── 遍历 model_variants 加载所有 variant 的各时段模型
│   │   └── models[variant_key][segment_name] = {backend, model}
│   ├── 加载价格区间模型 → models["__price_interval__"]
│   └── 加载火电开机容量模型 → models["__thermal_capacity__"]
├── load_forecast_generic()：加载并解析预测文件
│   ├── 识别预测日供需特征列
│   ├── 识别参考日数据（如果模板包含）
│   └── 返回 forecast_df, template_reference_df
└── assign_segments()：按模型时段配置给历史+预测数据分配 segment
```

#### 步骤 2：预测火电开机容量

```
predict_thermal_capacity_value(forecast_df, thermal_model, file_value)
  ├── 如果有日级开机容量模型，会先计算一个 model_value
  ├── build_thermal_capacity_choice() 再按配置选择来源
  │   ├── mode="model"：使用模型预测值
  │   └── 默认 mode="manual"：使用手动值；没有手动值时回退到预测模板中的文件值
  └── apply_thermal_capacity_choice() 填充 forecast_df["thermal_on_capacity"] 并记录来源
```

#### 步骤 3：构建相似法参考帧 → build_reference_frame()

```
根据 reference_strategy（"最近N天" 或 "最近N个同类型日"）：
  ├── 优先使用预测模板中的参考日数据（模板参考日优先级最高）
  ├── 不足时从历史数据中补充
  └── 生成 reference_df（参考日 96 点数据）和 reference_dates
```

#### 步骤 4：给预测帧附加特征

```
attach_forecast_similarity_features(forecast_df, reference_df)
  ├── nearest_similarity_price()：仅火电空间相似法
  │   └── 对每个预测点，在参考日中找 net_load 最接近的点
  │   └── 输出 similar_price / similar_gap
  ├── multi_factor_knn_similarity_price()：多因子 KNN 相似法
  │   ├── 特征：net_load, total_load, renewable_power, thermal_on_capacity, thermal_space_load_ratio, period, day_type
  │   ├── k=5, max_distance=3.0
  │   ├── 加权回归预测 weighted_knn_price
  │   └── 输出 knn_similar_price / weighted_knn_price / count / distance

attach_forecast_lag_features(forecast_df, history_df)
  ├── price_lag_1d/2d/3d/7d：历史同期价格滞后
  ├── price_ma_3d/7d：历史移动平均
  ├── price_std_7d：历史波动率
  └── net_load_lag_1d：历史同期负荷
```

**注意：** lag 特征仅在预测帧需要匹配历史数据时用到（如 with_lag_96 变体）。当前已训练版本中，部分时段使用 with_lag_96，部分时段使用 no_lag_96。

#### 步骤 5：按时段分段预测（核心）

```
对每个 segment（按 metadata["segments"] 顺序）：
  ├── segment_df = forecast_df[segment == name]
  ├── select_segment_prediction_model_variant(metadata, segment_name, forecast_df)
  │   ├── 优先从 selected_segment_price_models 取该时段独立选择的模型
  │   └── 如没有则 fallback 到全局 selected_model_key
  ├── 取该 variant 的 feature_columns
  ├── 取该 variant 该时段已加载的 model
  ├── predict_backend_model(model, backend, segment_df, feature_columns)
  │   ├── XGBoost: xgb.DMatrix + model.predict()
  │   ├── LightGBM: model.predict()
  │   └── CatBoost: model.predict()
  ├── clip_price_series(raw_pred)：裁剪到 [0, 1500]
  ├── segment_df["predicted_price"] = clipped
  ├── segment_df["model_variant"] = variant_key（记录用了哪个模型）
  ├── segment_df["model_similarity_diff"] = predicted_price - net_load_only_similar_price
  └── segment_df["residual_pred"] = model_similarity_diff（仅兼容旧字段）

合并所有时段 → result_df，按 date + period 排序
```

**关键：每个时段可以使用不同的模型。** 当前已训练版本是在 `with_lag_96_xgboost` 和 `no_lag_96_xgboost` 之间按时段选择；重新用 `.venv` 训练后，才可能出现 XGBoost / LightGBM / CatBoost 混用。

#### 步骤 6：叠加价格区间预测

```
如果 models 中有 __price_interval__（区间模型存在）：
  ├── predict_interval_probabilities(result_df, interval_bundle)
  │   ├── 按时段加载对应区间分类模型
  │   └── 预测每个时点属于各区间的概率
  ├── append_interval_prediction_columns(result_df, ...)
  │   ├── predicted_interval：最可能的区间（如 "300-400"）
  │   ├── predicted_interval_probability：该区间概率
  │   ├── high_price_probability：高价概率（>=600区间的概率之和）
  │   ├── extreme_price_probability：极端高价概率（>=1000区间概率）
  │   ├── interval_backtest_accuracy：该区间模型的历史命中率
  │   └── price_interval_consistency：区间一致性提示
  └── apply_high_price_probability_adjustment(result_df)
      生成 high_price_adjusted_price / high_price_adjustment 等附加列
```

区间模型不覆盖基础预测价格 `predicted_price`。`apply_high_price_probability_adjustment()` 会生成 `high_price_adjusted_price` 等附加列，用于查看高价概率上调后的参考值。

#### 步骤 7：导出结果

```
export_prediction(result_df, output_file)
  ├── 输出到 output/dayahead_price_prediction.xlsx
  └── 当前主流程只导出结果文件；`write_prediction_to_template()` 函数存在，但 `predict_prices()` / `predict_prices_compare()` 返回的 template_updated=False，当前没有自动回填预测文件。
```

## 第三部分：关键逻辑核对清单

以下逐一检查当前逻辑与你可能关心的点：

### ✅ 模型训练目标
- **当前：** 直接预测 `日前出清价格(元/MWh)`（不是残差）
- **不使用：** `similar_price` 作为训练特征，不训练 `residual_target`
- **结论：** 这是"直接价格模型"，不是过去的"相似法+残差修正"

### ✅ 分时段建模
- **当前：** 6 个时段各自独立训练，各自有模型文件
- **每个时段：** 独立划分训练集/验证集（按时段内日期切分）

### ✅ 多后端自动比较
- **当前：** XGBoost / LightGBM / CatBoost 可用时都会训练
- **选择逻辑：** MAE + 0.2 × RMSE 综合得分，选得分最低的
- **当前已训练版本默认选中：** `with_lag_96_xgboost`；重新用 `.venv` 训练后才会重新比较三后端。

### ✅ 每个时段独立选模型（2026-05 新增）
- **selected_segment_price_models：** 每个时段可独立选择最佳后端
- **预测时：** 每个时段用自己的选中模型
- **如果未配置：** 回退到全局 selected_model_key

### ✅ 验证集来自时间序列末尾
- **切分方式：** 按时段内日期排序，最后 N 天做验证集
- **不是随机抽样：** 保证验证集更接近未来预测场景

### ✅ 高价样本加权
- **当前启用：** enabled=true, quantile=0.8, multiplier=2.0, threshold≈323
- **作用：** 价格 >= 323 的样本训练权重翻倍
- **不影响验证集评估**

### ✅ 价格区间分类模型
- **独立训练：** 不参与具体价格预测
- **作用：** 预测页面展示风险提示（高价概率、区间命中率等）
- **高价调权：** 生成高价概率上调后的附加价格列，不覆盖主预测价 `predicted_price`

### ✅ 滚动回测
- **默认 14/30 天：** 模拟历史预测评估稳定性
- **仅在训练完成后执行：** 不影响训练结果

### ✅ 模型版本管理
- **三层结构：** current / previous / history/run_xxx
- **保护逻辑：** 训练失败自动恢复上一版模型
- **支持回退：** rollback 命令可回到 previous

### ✅ 相似法角色
- **不参与训练：** 不作为特征或标签
- **预测时输出：** 作为参考曲线/基线
- **两条基线：** 仅火电空间相似法 + 多因子KNN相似法

### ⚠️ 特征变体数量
- **之前文档说 3 个变体：** no_lag_96 / with_lag_96 / with_lag_knn_96
- **当前代码实际：** `direct_model_variants()` 返回 `no_lag_96` 和 `with_lag_96` 两个变体
- **影响：** 完整候选模型数从 3×3×6=54 降为 2×3×6=36（不含回测和区间模型）；当前已训练旧版本因只识别到 XGBoost，所以 metadata 中只有 2×1×6。

### ⚠️ 火电开机容量模型
- **新增功能：** 2026-05 左右加入
- **日级模型：** 用日级特征预测当日火电开机总容量
- **预测时：** 用于填充 forecast_df["thermal_on_capacity"]

### ⚠️ metadata 冗余
- **代码简化分析报告指出：** metadata 字典中存在大量重复嵌套（training_mode 计算重复 6 次）
- **功能上正确：** 但结构冗余，后续可优化
