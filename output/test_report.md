### 🟡 中等问题 (3 个)

#### 3. morning_peak 模型 best_iteration=0，残差模型未生效

当前激活模型 (`run_20260428_221715`) 的元数据显示：

```
morning_peak:
  baseline_mae: 65.90  →  final_mae: 67.56   (变差了)
  baseline_rmse: 151.21 → final_rmse: 151.92  (变差了)
  best_iteration: 0
```

**问题**: 
- `best_iteration=0` 说明早启停在第 1 轮就触发了
- 残差模型预测反而比相似法基线更差 (MAE 从 65.9 升至 67.6)
- 这意味着对早高峰时段，XGBoost 残差修正完全没有正向作用

**影响**: 该时段的预测精度由相似法基线主导，模型没有带来提升。

**可能原因**: 
- 训练数据量偏少 (当前模型仅 7968 样本 vs 上一版 47904)
- 早高峰价格波动大，特征不足以捕捉残差规律

#### 4. 训练后 pinned_default 版本覆盖新模型返回值混乱

`train_and_register` 函数 (dayahead_core.py:697-699):

```python
pinned_version_key = read_pinned_default_version(config.model_root)
if pinned_version_key and pinned_version_key != run_id:
    current_dir = activate_model_version(config.model_root, pinned_version_key, persist_default=False)
```

随后返回的 `TrainResult` 中 `current_model_dir` 指向的是 pinned 版本目录，而非新训练模型的目录。但 `metadata_path` 也使用了被覆盖后的 `current_dir`。

**影响**: 如果用户锁定了某个默认版本，训练完毕后返回结果中的目录路径和元数据路径均指向旧模型，而非刚训练的模型。

### 🟢 轻微问题 (4 个)

#### 6. 模型元数据中存储了绝对路径

```json
"train_config": {
    "history_dir": "D:\\每日工作\\代码示例\\预测程序-------\\demo1\\数据",
    ...
}
```

元数据中包含 Windows 绝对路径。如果项目被移动到其他位置，这些记录就过时了。

#### 7. `write_prediction_to_template` 无验证保护

该函数直接将预测值写回模板文件，没有任何保护措施：
- 没有备份原始模板
- 没有验证目标列是否存在（找到第一个含"预测价格"的列即写入）
- 写入的单元格从第 2 行开始，假定第 1 行是表头，第 2-97 行对应时段 1-96

如果模板格式有变化，可能导致数据错位。

#### 8. 数据中存在 2026 年日期但无对应数据文件

当前模型的训练日期范围是 2026-01-01 到 2026-03-09，但在 `数据/` 目录下没有找到 `2026年/` 子目录。这些 2026 年的数据可能存储在某个现有 Excel 文件的 Sheet 中，或通过其他方式提供。如果数据源变更，训练可能失败。

#### 9. Web 前端目录存在性未验证

`api_server.py` 引用 `FRONTEND_APP_DIR = BASE_DIR / "frontend_app"`，但 project 中未找到对应的前端文件（仅在 glob 中看到 `frontend/` 目录用于 streamlit）。
